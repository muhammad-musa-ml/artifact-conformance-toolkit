LINT-BANNED-NAMES -- THE RED TRANSCRIPT
====================================================

WHAT the banned-spelling rule REQUIRES, verbatim from the context note:

    `<redacted-path>` is banned outright. conformance.py FAILS on its existence
    in any artifact, and a repo-wide lint FAILS on the literal string in any
    plan or doc. G2 is a BLOCKER because an earlier round gives the ambiguity eighteen
    chances to be inherited; the lint gives that sweep a mechanical needle.

(The path itself is redacted throughout this file, and so is every span the
capture below echoes. See "THE TOOL NEVER PRINTS ITS OWN NEEDLE".)

THE PROBLEM, WHICH IS NOT "FIND THE STRING"
--------------------------------------------
The literal is already in this repository many times over, and almost every one
of those occurrences IS THE DECISION RECORD THAT CREATES THE BAN. A lint written
as "FAIL on the literal in any plan or doc" is red on day one, on its own
charter. The two repairs a maintainer reaches for both destroy it: weaken the
rule, and the ban stops being enforceable; add an exclusion list, and it grows
every time anyone documents the ban.

A third repair looks better and is the same mistake in better clothes: key the
classification on the DIRECTORY. MEASURED against this tree, a rule reading
"LIVE in templates/, tools/ or any *-PLAN.md" classifies tools/
lint_banned_names.py itself, tools/conformance.py, and a dozen plan lines that
INSTRUCT the ban's enforcement as violations of the ban they enforce.

AND THE POPULATION GROWS, RE-DERIVED RATHER THAN QUOTED
--------------------------------------------------------
Measured by this tool at the moment of this capture, over the tracked files of
this worktree:

    listed 174, scanned 174, files with a hit 14
    occurrences 41, lines carrying a hit 34

The two figures differ because one generated HTML file holds several hits on two
long lines, so an occurrence-count lint and a line-count lint give DIFFERENT
answers. Both are printed. The research note states the literal "appears 15 times
in this repo"; that figure was correct when it was taken and is not correct now.
Nothing in the detector hard-codes any of them -- a test greps its source for
every figure the planning documents quote and requires zero hits.

THE FOUR ROLES, AND WHY THE DEFAULT IS THE LOAD-BEARING PART
--------------------------------------------------------------
  DETECTOR   a needle, a fixture payload, or a test or acceptance criterion
             naming the path in order to prove it is CAUGHT. Never a finding.
  FROZEN     a document quoting, naming or describing the ban in order to
             EXPLAIN it. Never a finding.
  LIVE       a real FILE at that path, or prose INSTRUCTING an author to write,
             emit, read or consume it. A finding.
  UNCLASSIFIED  the DEFAULT. Not a role: a hit no cue describes is printed with
             its span, counted, and exits non-zero.

Defaulting to FROZEN would make every hit the cue lists fail to describe vanish
into a count nobody reads, and the LIVE arm would shrink to the file-exists check
conformance.py already performs inside an artifact -- which is precisely the
needle the banned-spelling rule says the eighteen-plan sweep must have and would not need this tool
for. Defaulting to LIVE would make the lint red on day one and invite the
exclusion list. UNCLASSIFIED is neither: ambiguity becomes a COUNT the owner must
close, one hit at a time, by an IN-PLACE ADJUDICATION -- a short note beside the
hit, inside its span, that supplies a cue. Widening a cue set to sweep up an
inconvenient hit is NOT sanctioned, and neither is an exclusion list.

THE TOOL NEVER PRINTS ITS OWN NEEDLE
-------------------------------------
Every span this tool reports is echoed with the path replaced by
`<redacted-path>`, and the header line names the DECISION rather than the
spelling. Without that, this transcript, every report file and every failing
assertion message that quotes a span would seed the literal into files the lint
scans -- the tool reading its own output back to itself, with a fresh crop of
hits nobody wrote by hand. tools/conformance.py's the banned-spelling rule guard declines to spell
it in its PASS note for the same reason, and the placeholder is asserted to
contain no word any cue table fires on, so a redacted span cannot acquire a cue
it did not have.

The detector's own source, and conformance.py's, each carry ZERO occurrences:
the needle is assembled at run time from a directory component and a filename
component held as separate strings. A detector carrying its own needle reports
itself on every run, and the obvious repair -- excluding the detector's own path
-- is the exclusion list this design exists to avoid.

CUES MATCH ON WORD BOUNDARIES
------------------------------
A substring reading of "the span contains `ban`" fires on `urban`; of `not` on
`nothing` and `note`; of `read` on `already` and `thread`. A cue set matching
those classifies by accident, which is the failure this design is about. Two
sentences in the suite exist only to pin this: "The urban pipeline writes X
nightly" and "Nothing in the notes writes X here" are both LIVE, and only a
substring match could see a prohibition in either.

WHAT MAKES THIS A REAL RED RATHER THAN A MISSING FILE
------------------------------------------------------
a design rule requires the transcript to be captured BEFORE the implementation commit.
The trap is that "before the implementation" reads as "before any code exists",
and a transcript captured then records a module that could not be imported. Each
of those exits non-zero, each satisfies a naive "non-zero exit" acceptance test,
and none says anything about whether the lint DISCRIMINATES. an earlier plan's RED
transcript failed its OWN gate because its first draft pasted the grep pattern
it was documenting; an earlier plan's first capture was a false RED because a pin read
an expectation file that did not exist.

So tools/lint_banned_names.py was RUNNABLE when this was captured. It tested its
own needle against a path assembled from the same parts, enumerated the tracked
tree through `git ls-files`, read every file, located every hit, computed every
span, resolved arm 0 against the real filesystem, counted occurrences AND lines
separately, listed the cues that matched nothing, and printed all four role
counts beside the effective file floor. ONE function was stubbed:

    classify()   returns LIVE for every hit, whatever the sentence says

So the summary line read `live 41, frozen 0, detector 0, unclassified 0` and the
failures below are assertions about a VERDICT.

THE COMMAND
------------
    python -m pytest tools/tests/test_banned_names.py -q > .reports/p0112-red-lint.txt 2>&1
    echo "EXIT=$?"     ->  EXIT=1

Redirected rather than piped, and the exit code read from $? of the REAL command.
A command piped into tail returns the PIPE's status, which is how "EXIT=0" gets
printed beside a failing run.
